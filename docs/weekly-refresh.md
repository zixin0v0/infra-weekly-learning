# 开始一个单元前，怎样更新资料

[整体安排](curriculum-design.md) · [进展索引](../resources/frontier-watchlist.md) · [记录模板](../templates/weekly-refresh.md)

第一次开始单元、隔了一段时间回来，或旧接口导致实验无法运行时，做一次更新。按实际开课日期核验，2026-10-01 的资料只能代表当时查到的情况。目前没有后台自动更新任务。

## 用30分钟做这几件事

| 时间 | 做什么 | 记下什么 |
| --- | --- | --- |
| 0～5分钟 | 看本周问题、先修要求和 context.md，确认执行设备 | 这次学什么，哪些条件还没确认 |
| 5～15分钟 | 查官方稳定文档和发布记录，核对原阅读位置与接口 | 链接、访问日、版本，以及影响本周的变化 |
| 15～25分钟 | 重查本周关注的方向；需要替换时，最多再找一篇论文或作者实现 | 它解决什么问题，试验条件与自己有什么不同 |
| 25～30分钟 | 决定保留、替换、继续观察或暂不适用 | 短记录；若替换资料，说明删去什么和时间安排 |

没发现可靠变化就保留原安排。页面打不开时记“未核验”，不要靠搜索摘要猜 API。30分钟用于查资料，安装、编译和硬件检查需要另外安排。

## 哪些变化值得改进课程

先看官方稳定文档、发布说明和支持条件，再看作者论文与代码。社区讲解可以帮助理解，涉及接口和性能保证时仍回到一手来源。

新材料进入必读范围前，要能回答：与本周问题有什么关系？具体读哪里？硬件和先修是否满足？怎样检查结果？它替换哪一段？这些说不清，就先记为选修。

记录中分别写清两件事：

- 项目现在处于什么阶段：论文、作者原型、experimental / beta、稳定接口，或已有具体部署案例。按来源说明，查不到就写未知。
- 自己验证到了哪里：仅阅读、能运行、已复现，或已经接入自己的系统。官方项目发布了，不代表自己已经验证过。

性能结论还要带上硬件、dtype、输入/负载、对照版本、质量要求和计时范围。`latest`、`main`、`dev` 都会变化，运行前应选定版本。发布日期、访问日期和实验日期分别记录；不知道发布日期就留空或写未知。

## 更新后保存在哪里

1. 在当前单元目录创建 `refresh-YYYY-MM-DD.md`，使用 [模板](../templates/weekly-refresh.md) 记录来源与决定。同日再次核验可追加在同一文件。
2. 更新 `context.md` 的日期、说明与阅读位置。只有必读内容或实验要求改变，才修改导学和 README；改变顺序时还要同步导航。
3. 在 [进度表](progress.md) 链接这次更新，填写实际学习状态。历史记录留在各单元目录。

运行前记录实际环境、框架和项目版本、模型/tokenizer revision、配置与输入来源。未安装时填“待选”，不能拿网页版本替本机填值。已完成的实验保留原配置和数据。

## 一次备多个单元时

可以按备课日期为未来单元保存来源复核，并准备三份 `session-XX.md`，但标明“资料已核验、学习未开始”；不把其余单元改成进行中。实际开课日重新检查依赖、支持条件和资料变化，同日追加记录，跨日新建更新文件。当前八个单元的记录见 [备课总入口](first-eight-weeks.md)。

## 下次开课可以这样说

> 开始学习 WXX。请读它的 README、study-guide、context 和最近的更新记录，确认先修和执行环境，再联网核对指定官方资料及一个相关进展。说明现在常用的做法、新方法的条件，以及从论文到实际使用还缺什么。把修改写回本地；资料仍控制在150分钟，新增必读内容要说明替换了什么。然后给出今天第一段的阅读位置、中文重点、动手练习和检查方法。没有运行的项目标明未验证。

无需每周从零搜索十几套框架。先用实验找到自己缺什么，再决定下一步补什么。
