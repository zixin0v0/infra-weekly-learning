# 项目结构与文件管理

[总路线](../README.md) · [前八个学习位置](first-eight-weeks.md) · [实验约定](../labs/README.md) · [GitHub 推送](github-publishing.md)

学习材料与个人记录各有固定位置。同一实验只保留一份实现，日期用于标识复核或真实运行，单元编号和段编号用于保持导航稳定。

```text
infra-learning/
├── README.md                         总路线与当前入口
├── docs/
│   ├── first-eight-weeks.md           8 个学习位置、24 段自学导航
│   ├── study-guide.md                 共用阅读辅助与定位规则
│   ├── progress.md                    实际学习与验收状态
│   └── repository-layout.md           文件职责与归档约定
├── weeks/week-XX-topic/
│   ├── README.md                     单元范围、验收和实验链接
│   ├── context.md                    当前做法与一个相关方向
│   ├── study-guide.md                前八单元三段导航；后八单元完整三段
│   ├── session-01.md                 第一段详细学习指南
│   ├── session-02.md                 第二段详细学习指南
│   ├── session-03.md                 第三段详细学习指南
│   └── refresh-YYYY-MM-DD.md          来源、版本、成熟度与保留决定
├── resources/                        共用来源索引
├── templates/                        学习指南、更新和报告模板
├── labs/                             动手开始后创建唯一实现与记录
└── projects/                         跨单元入口，链接复用 labs
```

`week-13-systems` 保留原路径，学习位置是第 7 个；`week-07-collectives` 的位置是第 8 个。不要为调整顺序改名，也不要再建立第二套 `week-07-compile` 目录。

## 文件职责

| 内容 | 存在哪里 | 怎样维护 |
| --- | --- | --- |
| 学习目标、范围、周验收 | 周 `README.md` | 范围改变时同步三段安排和完成标准；验收状态依据证据 |
| 精读起止、中文解释、暂停题 | 前八单元 `session-XX.md`；后八单元 `study-guide.md` | 段编号保持稳定；使用 [分段学习模板](../templates/study-session.md) |
| 三段安排与共用链接 | 周 `study-guide.md` | 提供概览并链接学习指南，前八单元不重复 session 正文；后八单元直接提供完整三段 |
| 官方来源与版本决定 | 周 `refresh-YYYY-MM-DD.md` | 同日补查追加，跨日期新建；旧实验保留原配置 |
| 你预测、作答、卡点 | 实验 `notes.md` | 按段号分节，在观察后追加，保留原预测 |
| 代码、配置、小型数据、报告 | 对应唯一 `labs/` 目录 | 动手时创建，不用占位结果表示完成 |
| 跨周复用 | `projects/` 的 README 与必要编排入口 | 链接原实现；已有代码不复制一份 |

## 实验目录什么时候创建

例如 W5 实际动手时，沿用规划路径创建：

```text
labs/03-triton-attention/softmax/
├── README.md               问题、复现入口、支持范围
├── notes.md                三段预测、作答和阅读位置
├── softmax.py              真实实现，文件名在动手时确定
├── config.json             输入、dtype、种子和计时约定
├── environment.txt         本次实际软件与设备
├── report.md               由记录整理的一个周报告
├── results/YYYY-MM-DD-run-01/
│   ├── raw.csv             真实逐次测量
│   └── summary.csv         从同次 raw 数据生成的汇总
└── figures/                由真实数据生成的图与绘图脚本
```

这是未来目录约定，当前没有这些实现和测量。日期相同的独立测量递增 `run-01`、`run-02`；在报告中指明配置和原始数据。失败、OOM 和未完成检查有独立记录，不填示例数字或零。

当前学习指南的原创概念图使用 Markdown 内嵌 Mermaid 或静态表格，源文件就是所在分段学习指南；图下注明它是机制示意或理论推导。未来实测图保留绘图入口、输入数据与导出文件，不能将概念图伪装成测量曲线。

## 提交与忽略

- 提交：Markdown 规则、学习指南与更新记录、原创概念图、实现代码、配置、可公开的环境摘要、小型原始数据和报告。
- 忽略：`.venv/`、编译产物、下载缓存、权重、checkpoint、大型 profiler trace、`.env` 和设备/服务凭据。
- 外部课程：记录原 URL、固定 commit / 版本、阅读范围和访问日；完整第三方 PDF / 源码下载留在临时目录。
- 机器日志：真实需要归档的短日志使用可公开的摘要或明确路径；`.log` 默认忽略，发布前移除凭据与个人连接信息。

提交前用 `git status --short` 和 `git diff --check` 核对改动，检查相对链接、来源与学习状态。只暂存当前任务的文件；推送到现有远程分支，远程有新提交时先比较并保留双方改动，使用普通快进推送。

## 状态怎样记录

指南整理状态保存在总入口和更新记录；学习状态保存在 [进度表](progress.md)。W1 已开始学习，其余十五个单元可以“学习指南已整理、学习未开始”。后续由“进行中”变为“已通过”需要实际阅读、代码、检查和报告证据。

每完成一段，在实验 `notes.md` 标明段号、日期与检查结果；完成单元时更新周实验链接和进度表。后续资料更新不覆盖旧运行的输入与版本。
