# 跨周项目

项目将独立实验整理成完整问题的答案。当前是项目范围设计，以下目录在开始整合时创建。

四个目录表示长期归档方向。当前优先整理 GPU 性能实验集与推理基线，训练和调度先完成小型可复现报告；不要求 16 个学习单元内交付四套成熟系统。

| 项目 | 单元 | 复用内容 | 完成标准 |
| --- | --- | --- | --- |
| `gpu-performance-lab/` | W2～W6、W13 | CUDA、Triton、Attention、torch.compile | 正确性、统一测量和一个模型区段的端到端观察 |
| `mini-serving-benchmark/` | W8～W10 | 服务基线、前缀缓存与负载实验 | 固定模型和请求集，报告延迟分位数、吞吐与失败率 |
| `distributed-training-lab/` | W7、W11～W12、W14 | 通信、DDP、FSDP2 与并行切分 | 公平对照、显存/通信分析、checkpoint 恢复 |
| `mini-gpu-scheduler/` | W15～W16 | Ray 执行与队列策略 | 固定任务轨迹，解释排队、公平性与完成时间 |

结构和归档约定见 [文件管理](../docs/repository-layout.md)，前八个学习位置的 [学习指南入口](../docs/first-eight-weeks.md) 独立于项目验收。

每个项目的 README 要有问题、架构、运行方式、实验配置、结果和局限。项目链接到 `labs/` 的已有实现；有新的编排入口时才在项目内新增代码。

W16 先仿真 FIFO/SJF，再按需接入任务提交层；这里控制提交顺序，并未修改 Ray 内部调度器。仿真结果与真实 GPU 运行分开呈现。

各项目直接使用已有实验，按 [阶段验收](../docs/curriculum-design.md) 整理。报告增加一个结论：对照现成实现，自己的方案在哪些条件下值得采用，哪里还缺验证。编译实验 W13 已提前，GPU 项目可在第7个学习位置开始整理。
