# 怎样学习和记录

[课程目录](README.md) · [我的进度](progress.md)

每次先确认先修，再看完整主题中的指定部分。到暂停点写下预测，遮住答案完成练习；保留错误答案和修正原因。示例能跑不等于独立实现；换输入并解释结果后，再做排错题。

完整主题可以分几次看。相同内容的视频和讲义不用重复计时；正文用于查图、代码和接口，必要补充按课页说明阅读。没有核验的时间点不会写成确定分钟数。

## 图怎样帮助理解

图中的输入通常从左边或上方进入。先找到对象，再沿箭头追踪数据或控制关系；内存格标的是元素位置，时间线会另外标单位。蓝色用于输入、紫色用于计算、绿色用于输出、橙色用于搬运或通信、灰色用于存储，文字标签仍是判断含义的依据。

每张图旁都有读图顺序和暂停题。图中的小例子用于讲清机制，后面的独立题会改变输入；先写自己的答案，再展开核对。PNG 适合直接阅读，图注中的 SVG 可以放大。理论数字和示意时间线不代表我的设备测量。

## 开始与结束一次学习

1. 从单元课表进入当前段。环境尚未就绪时先做纸面或 CPU 部分，将硬件验证留为待做。
2. 找到一处还不会解释的内容，先看示例，再补关键一步，最后从空文件独立实现。
3. 在对应实验目录的 notes.md 记录：日期、段号、观看或阅读范围、原预测、运行命令、检查结果和一个卡点。
4. 合上示例解释原因，换输入检查实现，再排查一个错误。还说不清或做不出的部分继续补做。
5. 完成后更新进度页，不在首页、单元页重复维护学习状态。

## 时间怎样安排

时间是规划范围，不作为内容上限或通过标准。W1/W11/W12/W15 各预计 **12～22 小时**，W2 **11～20 小时**，W6 **14～26 小时**，其余单元 **10～18 小时**；均包括阅读、图解、实现、测量和报告。数值、硬件、显存与重试的小节已包含在对应单元范围，不再额外加一次；另为每单元掌握检查的变式与排错预留 **1～3 小时**。这是未经过个人学习校准的范围，实际可超出。

基础阶段 P1～P7 预计 **24～48 小时**，P8 **4～8 小时**；C++、Tensor、模型、单卡训练按 [先修页](prerequisites.md) 各自范围，数学诊断通过的直接跳过。S1～S6 分别按 [桥接表](bridges/README.md) 计时；S1 已包含先修 A，不再重复。四次阶段复习各 **2～4 小时**，W16 综合自查 **6～10 小时**（含约束下的方案选择）。环境安装与下载单记，不混进阅读。

复用旧代码、旧数据和已有桥接检查时，仅计算新发生的学习时间；同一小时不能同时填在单元实现和综合掌握检查两处。建议记录 `预计范围 / 阅读实际 / 自查实际 / 实践实际 / 排错实际 / 环境实际`，完成一个单元后校准后续日历。

## AI 提示词怎样使用

每段的“可选：问 AI”围绕当段问题编写，可以全部跳过。先自行作答、看核对说明和原文，仍不清楚时再填入自己的预测、推导或真实日志；提示词中的方括号要换成自己的内容。

一次只解决一个疑问：请求一个小例子、一个反例或一次追问，保留自己完成实现与解释的机会。AI 对来源、接口和数字的说法，回到指定文档或运行结果核对；缺少资料时记为未确认。AI 说“正确”不替代本段完成要求，也不替你填写学习进度。

单次问答可先限制在 10 分钟内，替换卡点复习时间。若反复问仍不明白，记下具体疑问，回到较小的输入和先修章节，不继续堆提示词。

各段作答写进同一实验目录的 `notes.md`，用 `WXX-S01` 等段号或 `S1`～`S6` 标记。这样复习时能顺着预测、实现和修正找到原因，不必在多个笔记里找同一次实验。

## 性能实验的共同约定

- 区分正确性运行、计时运行与 profiler 采样；profiler 的额外开销不混入正式延迟。
- 固定输入、dtype、算法语义与精度设置。记录容差，不预设手写版本一定更快。
- GPU 计时要处理异步执行：写明 CUDA Event 或同步边界，区分 kernel 时间与端到端时间。
- 记录预热次数、重复次数、每次原始测量及汇总方式。建议先做 3 组独立测量；组内重复数按算子耗时调整。
- 保留编译、加载、冷缓存的成本，但与稳态结果分别报告。输入分配、数据传输是否计入要明确。
- 记录设备、软件版本、电源状态、其他负载和输入规模。不同设备的绝对值不直接解释为算法收益。
- 未测量值写“未测量”；失败或 OOM 单独记录，不能填成 0 或从报告中悄悄删除。
- 数值对齐与内存/同步检查分别记录；sanitizer 未报错不能证明任意输入都正确。
- 样本很少时将 p95 等分位数标为探索结果，报告请求数、测量窗口与多次运行的离散程度，避免只报一个最佳值。

## 从观察得出结论

算子表定位热点，系统时间线观察 CPU/拷贝/GPU/等待，kernel 指标解释算子内部行为。先找影响最大的区段，再深入测量，不要求每周同时使用全部工具。

服务实验同时记录计划到达率、实际发送速率、并发上限及是否触顶。并发限制可能反压请求生成器，“配置到达率不变”不能证明服务器收到的速率不变。区分成功请求吞吐、输出 token 吞吐和满足预先定义延迟目标的有效吞吐。

报告区分直接观察、机制推断与未验证假设。缓存开关、精度变化、编译开关和卡数变化分别做对照，避免一次改变多个因素后归因于其中一个。

原始小型 CSV/JSON 与图表可以随 Git 保存；权重、大型 trace 和 checkpoint 放在忽略的 `artifacts/` 或外部位置，在报告中记录来源与生成方法。

## 笔记与文章

笔记保存为 `notes.md`，论文笔记按需用 [论文模板](../templates/paper-note.md)。W3、W6、W8 可将实验报告整理成短文：讲清一个问题，用一张图说明结果，再写出结论和局限。无需另写长篇学习总结。

每段记录实际读到的章节/函数、一个预测、练习入口、检查结果和一个未解决问题。计划中列出的阅读位置不代表已经学完；未核对的视频时间戳保持空缺。

## 我的文件放在哪里

待补全代码与示例输入从 [练习材料](../exercises/README.md) 获取；自己的代码和结果放进 [labs](../labs/README.md)。同一实验只有一份实现，后续单元直接复用。报告使用 [实验记录模板](../templates/experiment-report.md)。

纸面推导、模拟输入、真实测量分别标注。新建结果文件必须来自一次实际运行，不填占位数字。开始日期、实际用时、命令与结果来源随实验记录。

## 资料与环境变化

第一次进入单元、久未使用或遇到旧接口错误时，核对官方页面和本机版本；变动记录放在维护区。开始学习只需了解影响当前操作的变化，不必通读审查记录。查不到的接口标为未确认，不用猜测补齐。
