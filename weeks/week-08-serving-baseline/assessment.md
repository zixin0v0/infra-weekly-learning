## W8：服务与请求生命周期

先完成 S2 请求和 S3 容器练习，自己补齐请求 JSON 的关键字段，再启动小模型服务。把一次请求的输入、日志与输出连起来，确认输出内容和长度后再运行压测。

**换个条件试试：** 某请求首 token 在发送后 100 ms、末 token 在 180 ms，共 5 个输出 token；协议在 200 ms 结束。计算 TTFT、平均后续 token 间隔 TPOT 和端到端延迟。再考虑只输出 1 个 token 的情况。

**找出问题：** 容器 Running 但请求连接失败，应检查哪些层？

<details><summary>展开核对推导；结果不同时，从这里检查</summary>

TTFT 为 100 ms，TPOT 为 `(180−100)/(5−1)=20 ms`，端到端延迟为 200 ms；只有 1 token 时后续间隔不存在，不填 0 当实测。先核对监听地址、宿主/容器端口、进程日志和就绪，再核对请求字段/模型；不能直接归因为 GPU。只测到 HTTP 200 仍要检查输出长度和内容。回 W8 第二/三段及 S2/S3。


先在时间线上标出发送、首 token、末 token 和协议结束。TPOT 计算后续 token 间隔，不能自动把最后一个 token 后的连接收尾算进去。 [回看请求时间线](session-01.md)。
