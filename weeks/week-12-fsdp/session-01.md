# W12 第 1 段：分片以后，显存到底省了哪几项？

[本单元](README.md) · [课程目录](../../course/README.md)

状态分片之前，先回 [W6 的对象寿命](../week-06-attention/session-04.md) 区分常驻状态与阶段峰值，并确认 [Adam 下一步恢复](../../course/foundations/training.md#resume) 的单卡比较已完成。

DDP 在每张卡上保留完整训练状态；分片把其中一些长期状态分开保存。它可以降低重复存储，但不会自动让激活、临时缓冲和执行峰值都按卡数缩小。

## 把长期持有状态与执行时临时数据分开

**状态分片（state sharding）**讨论谁长期保存参数、梯度和优化器状态。某个时刻只持有一半参数，不代表计算时从不需要完整参数；执行具体层前，可能先通过 AllGather 聚合相应参数，之后再按策略释放或重分片。

因此先做两张表：一张列稳态状态归属，另一张列前向、反向和更新时可能同时存在的数据。下面的理想状态账本只回答第一张表的问题。下一段的[聚合图](session-02.md)解释为什么第二张表不能省略。

**例子与图解：DDP 与理想分片账本**

沿 W11 的 1024 个 FP32 参数、普通 FP32 Adam 算例：

| 状态 | DDP 每卡 | 理想 2 卡全分片每卡 |
| --- | --- | --- |
| 参数 | 4096 B | 2048 B |
| 梯度 | 4096 B | 2048 B |
| 两个逐参数 Adam 状态 | 8192 B | 4096 B |
| 上述合计 | 16384 B | 8192 B |

**暂停题**：表中状态减半，实测峰值显存是否必定减半？激活由此也分片了吗？

<details>
<summary>核对依据</summary>

不必然。执行层时会临时聚合参数，还包括激活、通信缓冲、临时工作区、元数据和分配器开销；激活不会仅因状态分片自动按卡数缩小。ZeRO 的阶段说明分片对象，不能直接视为 FSDP2 的一组同名开关。实际 dtype、优化器与混合精度配置需重新列账。

**动手练习**：给相同模型画 DDP 与理想分片状态表，写出随 world size 变化的部分和不会自动按卡数缩小的部分。

**检查结果**：不把论文的某个固定“每参数字节数”当作所有配置通用值，也不把 ZeRO 阶段与框架 API 机械等同。
