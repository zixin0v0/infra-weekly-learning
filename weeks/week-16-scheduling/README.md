## 实践任务

整合项目：projects/mini-gpu-scheduler/；复用 labs/07-scheduling/。

1. 定义固定任务轨迹：到达时间、资源需求、运行时长估计、实际运行时长与任务 ID。主线所有任务请求 1 个逻辑槽位，先用 1 个槽位手推，再扩到固定的多个槽位；避免混入多资源装箱问题。
2. 实现非抢占 FIFO 与 SJF，明确相同时长的排序和资源不足时的规则，两种策略使用相同容量。
3. 主线用离散事件仿真记录到达、派发、开始、结束与失败事件，保留与 W15 日志的字段映射。扩展运行 Ray 时由提交层控制尚未投递的任务，区分提交层等待与 Ray 内部等待；不声称修改 Ray 内部 scheduler。
4. 仿真中比较已知时长的理想 SJF 与有估计误差的 SJF，避免把事后知道的时长当作真实先验。
5. 比较平均/p95 排队时间、从到达到结束的完成时间、makespan 与长任务等待情况。
6. 计算资源分配率；只有真实 GPU 采样才能另行报告设备利用率。仿真与实测分表呈现。

多 GPU 需求、成组资源分配与真实硬件实验在基础验收后追加。有限任务集可以展示长任务等待加剧；讨论持续到达下的饥饿需要说明额外的到达假设。

## 验收

- [ ] 长任务等待和时长估计误差进入分析。
